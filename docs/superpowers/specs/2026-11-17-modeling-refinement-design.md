## 1. 意图与为什么

上一轮（A21）修完了 3D 掉落物的可见性与拾取，实机确认通过。审查后发现：
**所有实体类别都已有 3D 模型，建模缺口为 0**。当前视觉短板不是"缺模型"，
而是"已有模型质量分层明显"——30 种怪物仍是第一版方块拼装（平均 855 面/件），
而 Boss/玩家/NPC 已精修（2,000–9,000 面/件）。这正是 A17 批次承诺的
"先铺开，再二次精修"尚未兑现的部分。

本立项的目标：按优先级和复杂度，用 Blender MCP 分批精修现有模型，
把质量最低的类别提升到与其他类别一致的水准，同时清理审查发现的资产卫生问题。

## 2. 目标 / 非目标 / 反目标

**目标**
- 每批模型在 Blender 中手建精修，导出 JSON 覆盖原文件，预览图同步更新。
- 严格沿用现有两套导出协议、明暗烘焙表、命名与坐标规范（见审查报告 §4）。
- 每批做到：资产校验（面数/NaN/name 一致）+ 预览图 + 必要的 C++ 单测 + 实机截图验收。
- 按优先级从高到低、复杂度从低到高排序，分批推进，每批可独立验收。

**非目标**
- 不新增实体种类、不改 gameplay/RNG/存档/骨架/动画系统。
- 不引入外部资产库（polyhaven/sketchfab/polypizza 均未开启，且风格不符）。
- 不动 2D 像素素材与 UI。

**反目标（做了就算失败）**
- 破坏现有模型命名/schema 导致加载失败。
- 用 AI 生成器（`generate_3d`）产出——风格与顶点色烘焙管线不兼容，且会产生费用。
- 一次性铺开 30 种怪物导致无法逐族验收、无法回退。

## 3. 约束

- 引擎无实时光照，明暗必须烘进顶点色（SHADE 表固定）。
- 整件模型协议 A `(x,y,z)→(x,z,-y)`；角色部件协议 B `(x,y,z)→(x,-y,z)`，锚点在骨骼 pivot。
- 部件 y 可为负（挂在身侧的手臂/武器），是正常约定，不得"修正"为贴地。
- 现有参数化脚本可复用：`blender_models_monsters.py` / `boss_mcp_rebuild.py` 等。
- Blender MCP 已连接可用；禁用 `get_viewport_screenshot`/`get_world_state_snapshot`/`drain_human_activity`。
- 单件面数参考：怪物部件目标向 Boss 靠拢（约 1,200–2,000 面/件），避免超过 4,000 面/件。

## 3.5 精修的脚本架构（builder 审查补充，已定）

**逐怪覆盖，不改共享族模板。** `blender_models_monsters.py` 里 4 个 `FAMILIES`
模板（humanoid/orb/slime/construct）是 30 种怪物的共同基线。精修采用
**per-monster refinement**：在脚本中新增按怪物名索引的 `REFINEMENTS` 配置，
`build_parts(name)` 先调用共享族模板，再叠加该怪物的额外细节（追加部件、
配色层次、特征件）。

理由：若直接修改共享模板，重跑 `export_all()` 会静默改变其余 26 种怪物的
JSON，既让 P1 的脚本无法忠实重现自己的产物，也会把工作范围"隐形"扩到 150 件。
逐怪覆盖则保证：P1 产物可复现、其他怪物零影响、P2 铺开只需为剩余 26 种各写
一条 refinement 条目。

## 3.6 精修轮廓的物理边界（builder 审查补充，已定）

**不超出现有骨架 pivot 与部件包围盒包络。** 精修靠内部结构分层、特征部件、
配色/明暗层次提升观感，不靠放大轮廓。若某族确需外扩（如角、披风、更大武器），
必须：逐部件在 Blender 用 `look()` 检查与相邻部件/整体装配的穿插；
实机 `--hd2d` 截图确认不被裁切；否则回退该外扩。

依据：骨骼 `resources/animations/mon_<name>_skeleton.json` 的 pivot 与
`pixels_per_unit` 固定，`avatar_director.cpp:55-68` 按槽位 all-or-nothing 挂载，
超包络会穿模或被裁切。

## 4. 优先级与复杂度排序（建议，待拍板）

审查数据给出的候选工作，按"视觉收益 ÷ 工作量"排序：

| 优先级 | 工作 | 复杂度 | 收益 | 说明 |
|---|---|---|---|---|
| P0 | 资产卫生：删 2 个孤儿（`item_armor`/`item_robe`）+ 2 组重复墙（prison/volcano 的 `_v0`） | 低 | 低 | 纯清理，先做以建立基线；不影响运行时 |
| P1 | 怪物精修试点：挑 4 个预览图已有、辨识度高的族群（orc / slime / golem / fire_imp）做精修样板 | 中 | 高 | 验证"精修配方"和观感提升，作为后续批量模板 |
| P2 | 怪物精修铺开：剩余 26 种，按 4 形态族分批（humanoid / orb / slime / construct） | 高 | 高 | 逐族验收，复用 P1 样板与 `MONSTERS` 配色表 |
| P3 | 地标/道具细节层次：9 地标 + 10 道具 | 中 | 中 | 当前抽象几何，补层次；收益次于怪物 |
| P4 | 地形审美升级：21 件（尤其单调的地板/楼梯） | 高 | 中 | 影响全屏观感但工作量大、风险高，放最后 |

**建议本轮范围：P0 + P1**（清理 + 4 族怪物精修样板），产出可验收的样板后再决定是否推进 P2。
理由：怪物是唯一大面积低于水准的类别（150 件、均面最低），且 A17 已有明确承诺；
先做 4 族样板能用最小工作量验证"精修配方"，避免一次性铺开 30 种无法回退。

## 5. 分批方案（以建议范围 P0+P1 为例）

### 批次 0：资产卫生
- 删除 `assets/models/item_armor.json`、`item_robe.json`（确认仅注释引用）。
- 删除 `terrain_wall_prison_v0.json`、`terrain_wall_volcano_v0.json`（几何与基准完全相同）。
  - 注意：`terrain_wall_void_v0.json` 是近似变体，**保留**。
- 验收：全量 ctest 90/90；模型引用检查 0 缺失。

### 批次 1：怪物精修试点（4 族）
- 用 `blender_models_monsters.py` 的 `MONSTERS` 配色 + `FAMILIES` 模板作为基线，
  对 orc / slime / golem / fire_imp 四族做细节层次提升（结构分层、特征部件、配色层次）。
- 每族 5 槽（head/torso/arm/leg/weapon），共 20 件 JSON 覆盖。
- 每族产出：`monster_preview_<name>.png`（沿用命名）+ 装配三视图。
- 验收：JSON schema/面数/NaN 校验；`player_part_asset_test` 与模型资产单测；
  实机 `--hd2d` 截图对比精修前后；逐族 `look()` 审图。

### 后续批次（P2+，本次不展开）
待 P1 样板验收后，按形态族分批推进剩余 26 种，每批 5–8 族独立验收。

## 6. 交付物与验收门
